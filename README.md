# 연세솔안과 IOL 내비게이터

백내장 수술에서 **인공수정체(IOL)를 고를 때 쓰는 근거 기반 의사결정 보조 도구**입니다.
**환자 · 상담직원 · 의사** 세 가지 화면을 제공하고, 세 사람 사이에 입력값을 짧은 코드와 QR 로 넘길 수 있습니다. 한국어와 영어를 지원합니다.

**웹에서 바로 쓰기 → https://totenhaft.github.io/iol-navigator/**

> ⚠️ **의료 고지**
> 이 도구는 **임상 의사결정 보조(CDS)** 이며 **의료기기가 아닙니다.**
> 진단하지 않고, 처방하지 않으며, 담당 안과의사의 진찰과 판단을 대체하지 않습니다.
> 최종 인공수정체 선택은 반드시 실제 검사 소견과 집도의의 판단에 따라야 합니다.

## 세 개의 화면

| 화면 | 쓰는 사람 | 하는 일 |
|---|---|---|
| **환자** | 환자 본인 | 검사 수치 없이 생활 패턴·성향·아는 만큼의 눈 상태를 답합니다. 결과는 진료 상담을 준비하는 자료이고, 규칙 원문 대신 '진료 때 여쭤볼 것' 목록이 나옵니다. |
| **상담** | 상담직원 | 환자에게 대신 여쭤 입력하고, 검사실 계측값을 옮겨 적고, 렌즈 유형 비교표로 설명하고, 확인한 선택과 비용을 정리해 인쇄합니다. 판독이 필요한 항목(소대 상태, 불규칙난시, 토릭 계획)은 이 화면에 없습니다. |
| **의사** | 집도의 | 판독 소견과 계측값을 직접 넣고, 규칙별 근거 문헌·근거 수준까지 확인합니다. |

역할을 바꿔도 입력값은 그대로 유지됩니다.

## 환자 배부용 A5 결과지

결과 화면 아래 **`환자용 결과지 (A5)`** 버튼을 누르면 A5 한 장이 인쇄됩니다. 화면 결과와 담는 내용이 다릅니다 — 점수·규칙 번호·근거 등급은 빼고, **어떤 유형을 이야기했는지, 그게 어떤 렌즈인지, 무엇을 기억해야 하는지**만 남깁니다. 렌즈 설명과 검사 이름도 환자용 쉬운 표현을 따로 두고 씁니다.

- 성함·차트번호·담당의 칸은 **빈칸으로 인쇄**됩니다. 프로그램이 개인정보를 채우지 않습니다.
- 상담 화면에서 '선택 확인'을 해 두었다면 그 유형이, 아니면 1순위가 실립니다. 비용을 입력해 두었다면 함께 나옵니다.
- 인쇄할 때만 용지 규칙이 A5로 바뀌고 끝나면 A4로 되돌아옵니다. 전체 결과는 `전체 인쇄 · PDF` 버튼으로 A4에 뽑습니다.
- **테스트가 실제로 A5 PDF를 만들어 페이지 수를 셉니다.** 내용이 늘어 두 장이 되면 빌드가 실패합니다.

## 인계 코드 — 서버 없이 값 넘기기

이 도구에는 서버가 없습니다. 그래서 입력값을 **비트 단위로 압축한 짧은 코드**에 담아 넘깁니다.
`인계 코드` 버튼을 누르면 코드와 QR 이 함께 나오고, 받는 쪽은 코드를 붙여넣거나 QR 을 찍으면 됩니다.

```
2C88-PMY7-22K0-GJC9-34        ← 22자. 값을 적게 넣을수록 짧아집니다
확인 번호 4636                 ← "같은 코드 맞죠?" 를 말로 맞춰볼 때 쓰는 4자리
```

- **개인정보는 코드에 들어가지 않습니다.** 이름·생년월일·차트번호를 넣는 칸 자체가 없습니다. 사람 확인은 진료실에서 직접 합니다.
- 비어 있는 항목은 **비어 있는 채로** 넘어갑니다. 임의의 기본값으로 채우지 않는 이 도구의 원칙이 코드에서도 지켜집니다.
- 코드에는 입력 스키마의 **지문(fingerprint)** 이 함께 실립니다. 프로그램이 갱신되어 항목이 바뀌면 옛 코드는 *조용히 잘못 읽히는 대신* 명확히 거부됩니다.
- 헷갈리는 글자를 뺀 Crockford Base32 를 쓰고, `O↔0` `I↔1` 은 알아서 바로잡습니다. 소문자·공백으로 옮겨 적어도 읽힙니다.
- QR 생성기는 외부 라이브러리 없이 직접 구현했습니다(`src/js/06-qr.js`). 테스트가 만들어진 심볼을 **독립 디코더로 다시 읽어** 원문이 나오는지 확인합니다.

## 무엇을 하는가

입력한 눈 상태와 생활 요구를 7가지 렌즈 유형에 대해 평가하고, 다음을 보여줍니다.

- **추천 1순위**와 그 이유
- **대안**과 각각의 적합도 점수
- **피해야 할 유형**과 배제된 근거
- **확인할 추가 검사** 목록
- 각 판단에 연결된 **근거 문헌과 근거 수준**

비교 대상 6종. 토릭은 별개의 축으로 다룹니다.

| 유형 | 성격 |
|---|---|
| 단초점 | 한 거리에만 초점. 대비감도·야간 시질이 가장 안정 |
| 단초점 + 미니모노비전 | 양안 굴절을 달리해 범위 확보. 회절 광학 없음 |
| 프리미엄 단초점 (enhanced monofocal) | 비회절 중간거리 확장. **EDOF가 아님** |
| 연속초점 EDOF | 회절 링이 없는 연속초점 설계(이 진료의 실사용 렌즈 기준) |
| 굴절형 분절 이중초점 (렌티스) | 아래쪽 부채꼴 근거리 구역. add +2.0 / +3.0 D 를 눈에 따라 배정 |
| 다초점 · 삼중초점 | 전 시야범위. 안경 의존 최소 ↔ 헤일로 최대 |

**회절형·비회절형 EDOF를 나누지 않는 이유:** 이 진료에서 실제로 쓰는 연속초점 렌즈가 비회절 설계 한 갈래이기 때문입니다. 쓰지 않는 선택지를 화면에 남겨 두면 상담이 길어지기만 합니다. 같은 이유로 소구경(small-aperture) IOL도 뺐습니다.

## 설계에서 중요한 세 가지

**1. 용어를 국제 표준에 맞췄습니다.**
`프리미엄 단초점(enhanced monofocal)`은 EDOF가 **아닙니다.** ESCRS 기능적 분류상 Partial ROF의 `enhanced` 군이며, ISO 11979-7:2024 / ANSI Z80.35의 EDOF 초점심도 기준(0.20 logMAR에서 단초점 대비 +0.5 D)을 충족하지 않습니다. 국내에서 이 둘이 자주 혼용되기 때문에 도구 안에서 경계를 명시적으로 그었습니다.

**2. 단순 점수 합산이 아니라 3계층 로직입니다.**

| 계층 | 뜻 | 개수 |
|---|---|---|
| **금기(hard stop)** | 해당 렌즈를 후보에서 완전히 제외 | 12 |
| **주의(caution)** | 감점 + 사유와 조치를 함께 표시 | 26 |
| **권고(note)** | 감점 없는 임상 권고 | 5 |

어떤 입력에서도 **단초점은 배제되지 않고, 1순위는 항상 존재하며, 추가검사 목록은 비지 않습니다.** 이 세 가지는 테스트로 강제됩니다.

**3. 비용은 실제 금액으로 계산합니다.**
예전에는 렌즈마다 0~3짜리 '비용' 척도를 손으로 매겨 두고 그것으로 감점했습니다. 실제 금액을 쓰는 지금은 그 척도를 없앴습니다 — 화면에 찍히는 금액과 점수가 같은 표 하나에서 나옵니다.

| 유형 | 본인부담 (단안·비급여) |
|---|---|
| 단초점 (논토릭) · 미니모노비전 | 25만원 |
| 프리미엄 단초점 | 100–150만원 |
| 연속초점 EDOF | 200만원 |
| 굴절형 분절 이중초점 (렌티스) | 250–300만원 |
| 다초점 · 삼중초점 | 350–400만원 |
| 난시교정(토릭) 추가 | +75만원 |

감점은 `비용 민감도 × (그 렌즈 금액 − 가장 싼 금액) ÷ (가장 비싼 금액 − 가장 싼 금액)` 에 비례합니다. 싼 렌즈에 가산점을 주지는 않습니다.

**'상관없다'는 반대로 작동합니다.** 비용을 '상관없다'로 고르고 **탈안경 요구가 2 이상**이면, 초점 범위가 넓은 쪽(`근거리+중간거리 능력치`)에 가산이 붙습니다. 두 조건을 함께 요구하는 것이 핵심입니다.

- '상관없다'만으로는 올리지 않습니다. 탈안경을 원하지 않는다고 답한 환자에게 비싼 렌즈를 권하는 셈이 되기 때문입니다.
- **금액이 아니라 초점 범위에 비례시킵니다.** 가격 자체가 추천 사유가 되면, 환자도 보는 화면에서 '비싸서 골랐다'가 됩니다. 금액표를 뒤집어도 순위가 그대로인지 테스트가 확인합니다.
- 비용을 답하지 않은 것은 '상관없다'가 아니라 '아직 모름'이므로 제외합니다. 토릭은 모든 후보에 같은 금액이 더해지므로 순위를 바꾸지 않아 점수에서 빼고 표시에만 더합니다(테스트로 확인합니다).

금액은 상담 화면 `비용 설정`에서 병원이 고칠 수 있고, 고치면 **점수도 함께 바뀝니다.** 그 값은 해당 브라우저에만 저장됩니다.

**4. 빛번짐 감내 척도는 고르게 나뉘지 않습니다.**
겪어본 적 없는 증상이라 대부분 '조금은'이나 '웬만큼'을 고릅니다. 예전 계산에서는 그 한 칸이 회절형에서만 7점을 깎아 결과가 뒤집혔습니다. 지금은 `전혀 못 견딘다 2.0 / 조금은 0.5 / 웬만큼 0 / 충분히 0` 으로, **'전혀 못 견딘다'는 강하게 유지하되 '조금은'은 가벼운 유보로만** 반영합니다.

**5. 요구가 있을 때만 점수가 움직입니다.**
생활 요구 항목(안경 의존도, 근거리·중간거리 비중, 야간 운전, 빛번짐 감내, 비용)은 **미리 선택되어 있지 않습니다.** 고르지 않은 항목은 '요구 없음'이 아니라 '아직 모름'이므로 어느 쪽으로도 점수를 밀지 않고, 결과 상단에 미응답 목록으로 표시됩니다.
야간·빛번짐·비용은 **요구가 있을 때만 감점**으로 작동합니다. 요구가 없다고 해서 야간에 강한 렌즈에 가산점을 주지는 않습니다 — 그렇게 하면 아무 말도 하지 않은 환자에게 프리미엄 단초점이 1순위로 나오는 편향이 생깁니다(실제로 2026-08 이전 판이 그랬습니다).

**6. 근거가 약한 수치는 약하다고 화면에 씁니다.**
angle kappa 0.5–0.6 mm 기준을 쓰되 26,470안 연구에서 술후 결과와 무관했다는 점과 장비 간 편차(동일 안에서 0.27 vs 0.43 mm)를 같은 화면에 함께 싣습니다. 각막 고위수차 기준도 마찬가지입니다. 모든 규칙에 근거 수준 배지(A/B/C/D)와 문헌 링크가 붙습니다.

가장 간단한 방법은 **`index.html` 파일을 브라우저로 여는 것**입니다. 인터넷 연결 없이도 동작하고, 입력한 내용은 브라우저 밖으로 전송되지 않습니다.

```bash
git clone https://github.com/totenhaft/iol-navigator.git

```

주소 뒤에 `?test=1` 을 붙이면 임상 로직 자체 검증 90건이 화면에 출력됩니다.

## 고치는 법

`index.html` 은 **빌드 결과물이라 직접 고치지 마세요.** 원본은 `src/` 에 나뉘어 있습니다.

```
src/
├── head.html          디자인 토큰(색·글꼴)과 모든 CSS
├── body.html          화면 구조
└── js/
    ├── 01-data.js     근거 문헌 목록, 렌즈 7종 정의
    ├── 02-schema.js   입력 항목 (환자 / 상담 / 의사 화면)
    ├── 03-rules.js    ★ 의사결정 규칙 — 대부분의 수정은 여기서
    ├── 04-engine.js   규칙 실행과 점수 계산
    ├── 05-i18n.js     한국어·영어 문구, 용어 체계 표
    ├── 06-qr.js       QR 코드 생성 (외부 의존성 없음)
    ├── 07-handoff.js  인계 코드 압축·복원
    ├── 08-ui.js       화면 그리기
    └── 09-tests.js    임상 로직 자체 검증
```

고친 뒤 다시 합칩니다.

```bash
npm install     # 처음 한 번만
npm run build   # src/ → index.html
```

### 규칙 하나 추가하기

`src/js/03-rules.js` 의 `RULES` 배열에 객체 하나를 넣으면 끝입니다.

```js
{
  id: "규칙_고유이름",
  layer: "caution",                  // "stop"(금기) | "caution"(주의) | "note"(권고)
  targets: { trifocal: 2, edofDiff: 1.5 },   // 렌즈별 감점 (1 = 7점)
  when: d => d.어떤값 > 기준치,       // 조건. d 는 정규화된 입력값
  ko: { t: "제목", why: "왜 문제인지", act: "무엇을 할지" },
  en: { t: "...",  why: "...",        act: "..." },
  refs: ["R9"],                       // 01-data.js 의 문헌 ID
  grade: "C",                         // 근거 수준 A/B/C/D
  tests: [T.ABERRO]                   // '확인할 추가 검사'에 넣을 항목
}
```

`when` 안에서 값이 `null`(미입력)일 수 있다는 점만 주의하세요. `num(d.값) !== null && ...` 형태로 확인합니다. **미입력을 임의의 기본값으로 추론하지 않는 것이 이 도구의 원칙입니다.** 대신 '확인할 추가 검사'에 표시됩니다.

## 테스트

```bash
npm test
```

네 가지를 검사합니다.

- **QR 코드** — 만든 심볼을 규격에서 다시 구현한 **독립 디코더**로 읽어 원문이 나오는지. 리드-솔로몬은 인코더가 쓴 나눗셈이 아니라 신드롬 대입으로 검사하고, 형식정보는 두 벌이 일치하며 BCH 를 통과하는지 봅니다. 고정 입력 두 개는 골든 행렬로 고정해 두었습니다.
- **임상 로직 90건** — 시나리오(황반변성, 증식성 당뇨망막병증, 중증 녹내장, 안구표면질환, RK 후, 원추각막, 소대 불안정, 야간운전, 완벽주의 조합), 수치 경계값, 미입력 처리, **원장이 지적한 두 시나리오**(탈안경 요구 최대 / 근거리 맨눈 희망)가 실제로 연속초점 이상을 상위에 올리는지, 코마가 큰 눈에서 렌티스가 삼중초점보다 위로 오는지, 인계 코드 왕복, 역할별 스키마, 데이터 정합성
- **화면과 버튼 접근성** — 6개 화면 크기 × 3개 역할 × 4개 스크롤 위치에서 '결과 보기' 버튼이 실제로 보이고 눌리는지, 입력 필드가 눌리지 않고 끝까지 닿는지
- **역할 전환과 인계** — 환자 화면에서 넣은 값이 코드를 거쳐 상담 화면에서 **같은 1순위**를 만드는지, 잘못된 코드가 기존 입력을 지우지 않는지, `#h=` 링크로 열어도 채워지는지, **환자용 A5 결과지가 실제로 한 장에 들어가는지**

`main` 에 푸시하면 GitHub Actions가 자동으로 빌드 → 테스트 → 배포합니다. **테스트가 실패하면 배포되지 않습니다.** 임상 도구이므로 이 순서는 바꾸지 마세요.

## 알려진 한계

- 규칙별 **가중치는 문헌이 아니라 임상적 판단으로 정한 값**입니다. 실제 진료 데이터로 보정할 여지가 큽니다.
- **비용은 낡습니다.** 기본값은 연세솔안과 기준이며, 바뀌면 상담 화면에서 고치거나 `src/js/01-data.js` 의 `COST_DEFAULT_MAN` 을 고쳐야 합니다.
- **각막 코마가 클 때 굴절형 분절 이중초점(렌티스)을 쓰는 것은 이 진료의 임상 관행**입니다. 회절 링이 없어 고위수차를 덜 증폭한다는 광학적 근거는 있지만, 회절형과 직접 비교한 임상시험에 근거한 선택은 아닙니다. 도구 안에서도 근거 수준 D로 표시하고 그렇게 적어 두었습니다.
- 제목에는 병원 이름이 들어가지만 **화면 색상은 기존 청록 계열을 유지**합니다. 홈페이지의 골드(#AC9766)를 팔레트로 시험해 보았으나, 원장님 판단으로 되돌렸습니다. (참고: 그 골드는 흰 글씨와의 대비가 2.6:1 뿐이라 버튼·링크에 그대로 쓸 수 없고, 어둡게 조정한 값을 따로 만들어야 합니다.)
- **유통 렌즈 모델명 매핑은 넣지 않았습니다**(빠르게 낡고 검증이 어렵습니다). 비급여 비용은 병원이 상담 화면에서 직접 입력하며, 그 값은 **해당 브라우저에만** 남고 저장소나 서버로 가지 않습니다.
- 인계 코드는 같은 방문 안에서 넘기라고 만든 것입니다. 항목 구성이 바뀌면 예전 코드는 거부됩니다(잘못 읽는 것보다 낫다고 보았습니다).
- 양안 비대칭 설계(각 눈에 다른 렌즈)와 목표 굴절값 계산은 범위 밖입니다.
- 개인정보는 수집하지 않습니다. 서버가 없고 모든 계산이 브라우저 안에서 끝나며, 인계 코드에도 식별정보가 들어가지 않습니다.
